# Планирование междугородних рейсов на Java

ООП-версия программы КТ2: регистрация и проверка заявки, расчет времени в пути, подбор автомобиля и водителя, расчет стоимости и формирование рейсового задания.

## Сборка и запуск

Нужны JDK 25 и Maven 3.9.9 или новее. Команды выполняются из папки с этим README и pom.xml. Перед сборкой проверьте версии:

```text
java -version
mvn -version
```

В выводе обеих команд должна быть Java 25. Maven использует JAVA_HOME. При первой сборке нужен доступ к Maven Central для загрузки зависимостей.

```text
mvn clean package
java -jar target/planner.jar
```

Программа читает data/fleet.json и data/incoming.json относительно текущей папки. Явные пути можно указать так:

```text
java -jar target/planner.jar --fleet data/fleet.json --incoming data/incoming.json
```

При запуске из другой папки укажите абсолютные пути к обоим файлам данных и JAR. База данных и веб-сервер не требуются.

## Структура

1. Пакет com.mirea.freight.model содержит десять сущностей логической модели и подкласс RefrigeratedRequest.
2. Пакет com.mirea.freight.pricing содержит интерфейс CostRule, его две реализации и результат расчета CostResult.
3. Пакет com.mirea.freight.application содержит автопарк Fleet, координатор Planner, загрузчик JsonStore, результат PlanningResult и консольный запуск ConsoleApp.
4. В data находятся те же JSON-файлы, что у процедурной программы КТ2.
5. В src/test находятся тесты и ожидаемый вывод исходной программы.

Связи сущностей реализованы идентификаторами. Например, Trip.vehicleId ссылается на Vehicle.vehicleId. Fleet хранит коллекции и разрешает такие ссылки. Изменяемые списки не выдаются наружу для добавления и удаления элементов.

## Соответствие операциям КТ2

| Операция | Процедурная функция | Метод Java |
|---|---|---|
| Зарегистрировать заявку | register_request | Fleet.registerRequest |
| Проверить комплектность заявки | check_request | Request.checkCompleteness |
| Рассчитать время в пути | calc_travel_time | Planner.calcTravelTime |
| Подобрать автомобиль | select_vehicle | Fleet.selectVehicle |
| Подобрать водителя | select_driver | Fleet.selectDriver |
| Рассчитать стоимость перевозки | calc_cost | Planner.calcCost |
| Сформировать рейсовое задание | make_trip_task | Fleet.makeTripTask |

Подбор автомобиля сохраняет вложенный просмотр журнала рейсов и сложность O(n*m). Расчет цены ищет диапазон двоичным поиском за O(log b), после однократной подготовки тарифного индекса.

Request.checkCompleteness вызывает переопределяемый checkBody: подкласс RefrigeratedRequest требует температурный режим. Planner хранит StandardCostRule и DangerousCostRule через интерфейс CostRule и вызывает выбранную реализацию полиморфно. Опасный груз получает процентную надбавку и требует согласования.

## Проверка

```text
mvn test
```

В PlannerTest 12 тестов: полный вывод шести заявок, специализация заявки, реализации интерфейса, границы и пустая тарифная сетка, минимум цены и надбавка, занятость автомобиля, выбор водителя с действующим допуском, отсутствие резервирования при неполной заявке, повторная регистрация, защита коллекций и время в пути.

## Границы реализации

Программа повторяет процедурную версию КТ2. Маршрут и расстояние задаются входными данными. Скорость принята равной 60 км/ч. Согласование цены и ответы клиента остаются внешними действиями: программа возвращает соответствующий статус. Результаты хранятся в памяти до завершения запуска.
